WiFi met Arduino

Verbinding maken met draadloze netwerken en communiceren via moderne protocollen.

Doel van deze les

  • Begrijpen hoe WiFi werkt op een Arduino Uno WiFi Rev2
  • Gebruik van de WiFiNINA library en MQTT-communicatie
  • Verkennen van andere netwerkprotocollen (HTTP, CoAP, WebSocket, etc.)
  • Veilige en betrouwbare IoT-verbindingen opzetten

Arduino Uno WiFi Rev2 – Hardware

  • Microcontroller: ATmega4809 (8-bit, 16 MHz)
  • WiFi-module: u-blox NINA-W102 (gebaseerd op ESP32)
  • Geïntegreerde antenne + RF-shielding
  • Ondersteunt 2.4 GHz 802.11 b/g/n

De NINA-W102 WiFi-chipset

  • Gebaseerd op een Espressif ESP32 SoC
  • Bevat:
    • WiFi- en Bluetooth-stack
    • Interne flash-geheugen en CPU
    • SPI-communicatie met de ATmega4809
  • Firmware wordt aangestuurd via de WiFiNINA library

De NINA-module werkt als een “netwerk-coprocessor”: de ATmega stuurt opdrachten via SPI.

WiFiNINA Firmware

  • Bevat alle logica voor WiFi-verbinding, IP-stack en beveiliging
  • Kan worden geüpdatet via de Arduino IDE (Tools → Firmware Updater)
  • Versiebeheer is belangrijk voor compatibiliteit

#include 
void setup() {
  Serial.begin(9600);
  if (WiFi.status() == WL_NO_MODULE) {
    Serial.println("WiFi module niet gevonden!");
    while (true);
  }
  String fv = WiFi.firmwareVersion();
  Serial.print("Firmware versie: ");
  Serial.println(fv);
}

Netwerkconcepten

  • IP-adres: Unieke identificatie op het netwerk
  • DHCP: Automatische toewijzing van IP
  • DNS: Domeinnaam naar IP-adres vertalen
  • Poorten: Bepalen welk proces de data ontvangt

TCP vs UDP

  • TCP: Betrouwbaar, verbindingsgericht
  • UDP: Snel, geen foutcorrectie
  • Arduino ondersteunt beide via de WiFiNINA library

// TCP Client voorbeeld
WiFiClient client;
if (client.connect("example.com", 80)) {
  client.println("GET / HTTP/1.1");
  client.println("Host: example.com");
  client.println("Connection: close");
  client.println();
}

Overzicht van protocollen

  • HTTP/HTTPS – Webcommunicatie en REST API’s
  • MQTT – Lichtgewicht IoT-berichten
  • WebSocket – Real-time data
  • CoAP – Compact protocol voor sensornetwerken
  • SNTP – Tijd synchroniseren met internet
  • mDNS – Lokale netwerknaam-resolutie

HTTP en REST API’s

HTTP wordt vaak gebruikt om data te verzenden naar webservers of cloudplatforms.


WiFiClient client;
if (client.connect("api.thingspeak.com", 80)) {
  client.print("GET /update?api_key=XYZ&field1=25 HTTP/1.1\r\n");
  client.print("Host: api.thingspeak.com\r\n");
  client.print("Connection: close\r\n\r\n");
}

HTTPS vereist TLS-beveiliging en certificaatbeheer (WiFiSSLClient).

MQTT in detail

  • Client-server model met topics
  • Berichten kunnen worden gepubliseerd of ontvangen (subscribe)
  • Zeer efficiënt voor IoT sensordata

CoAP

  • Constrained Application Protocol (RFC 7252)
  • Lijkt op HTTP, maar werkt via UDP
  • Geschikt voor sensornetwerken met lage bandbreedte

WebSockets

  • Bidirectionele communicatie tussen client en server
  • Ideaal voor real-time dashboards
  • Kan worden gecombineerd met MQTT over WebSocket

Beveiliging en privacy

  • WPA2 – standaard WiFi-beveiliging
  • TLS/SSL – versleutelde verbindingen
  • API Keys – authenticatie voor online services
  • secrets.h – veilige opslag van wachtwoorden

// secrets.h
#define SECRET_SSID "MijnNetwerk"
#define SECRET_PASS "SuperGeheim!"

Toepassing 2 – Lokale webserver

Arduino kan zelf een eenvoudige webpagina hosten voor sensorwaarden.


WiFiServer server(80);
void loop() {
  WiFiClient client = server.available();
  if (client) {
    client.println("HTTP/1.1 200 OK");
    client.println("Content-Type: text/html");
    client.println();
    client.println("
Temperatuur: 23°C
");
  }
}

Toepassing 3 – OTA updates

  • OTA = Over-The-Air firmware updates
  • Vermijdt fysieke verbinding met USB
  • Wordt ondersteund via speciale WiFiNINA-firmwareversies

Debugging tips

  • Controleer WiFi.status() regelmatig
  • Gebruik Serial.print() voor statusmeldingen
  • Controleer firmwareversie bij verbindingsproblemen
  • Gebruik korte delays bij reconnects

Best practices

  • Vermijd gevoelige data in code
  • Gebruik retries en timeouts
  • Gebruik JSON voor gestructureerde data
  • Test op een stabiele WiFi-omgeving
